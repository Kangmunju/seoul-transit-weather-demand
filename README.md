
# 서울 지하철 수요 × 날씨 예측

### 💻 GitHub 저장소

서울·수도권 철도 승하차 이용량과 날씨 데이터를 결합하여
날씨와 지하철 수요 사이의 관계를 분석하고,
시간순 검증을 통해 수요 예측 모델을 평가한 프로젝트입니다.

단순히 모델의 예측 성능만 확인하지 않고
강우 효과의 교란 요인, 시계열 데이터 누수 가능성,
팬데믹에 따른 구조 변화까지 함께 분석했습니다.

2019~2024년 데이터를 기반으로
날씨 변수의 예측 기여도, 강우 강도별 이용량 차이,
학습 데이터의 시간적 구성에 따른 성능 변화,
고정 역 집합 기준 팬데믹 회복률을 검증했습니다.

또한 휴일 관련 특징을 추가하는 실험을 수행하고,
분석 결과를 Streamlit 대시보드와 포트폴리오 웹페이지에서
확인할 수 있도록 구성했습니다.

## 프로젝트 핵심 질문

- 비가 오면 지하철 이용량은 실제로 달라지는가?
- 요일과 계절을 통제해도 강우와 이용량 사이의 연관성이 남는가?
- 과거 수요와 날씨로 미래 수요를 예측할 수 있는가?
- 날씨 변수를 추가하면 실제로 예측 성능이 개선되는가?
- 무작위 데이터 분할은 시계열 모델의 성능을 과대평가할 수 있는가?
- 팬데믹 같은 구조 변화는 수요 예측에 어떤 영향을 주는가?
- 분석 대상 역의 구성을 고정해도 팬데믹 회복률이 비슷하게 나타나는가?
- 휴일 관련 특징을 추가하면 예측 성능이 개선되는가?

## 데이터

분석 기간은 **2019년 1월 1일부터 2024년 12월 31일까지**입니다.

지하철 승하차 이용량과 서울의 일별 날씨 데이터를 수집한 뒤
SQLite에 적재하고 전처리하여 분석에 사용했습니다.

주요 데이터는 다음과 같습니다.

- 지하철 일별 승하차 이용량
- 평균·최고·최저 기온
- 총강수량
- 강우량
- 적설량
- 최대 풍속
- 습도
- 요일·주말·공휴일 정보
- 팬데믹 국면 정보

### 데이터 규모

| 항목 | 규모 |
|---|---:|
| 분석 기간 | 2019~2024년 |
| 수집된 철도 노선 | 27개 |
| 원본 지하철 데이터 | 1,319,521행 |
| 승하차 구분 후 데이터 | 2,639,042행 |
| SQLite 적재 데이터 | 2,638,670행 |
| 일별 통합 데이터 | 2,192일 |
| 모델링 데이터 | 2,185일 |

승차와 하차를 합산한 이용량의 단위는
고유 이용자 수를 뜻하는 '명'이 아니라 **'건'**입니다.

현재 지하철 데이터에는 27개 노선이 포함되어 있으며,
수도권 전철의 모든 노선을 포함하지는 않습니다.

데이터 출처와 접근 방법은
[DATA_ACCESS.md](reports/DATA_ACCESS.md)에서 확인할 수 있습니다.

## 데이터 처리 흐름

```text
원본 데이터 수집
      ↓
원본 파일 검증
      ↓
SQLite 적재
      ↓
지하철·날씨 데이터 정제
      ↓
일 단위 집계
      ↓
지하철 + 날씨 병합
      ↓
달력·팬데믹 특징 생성
      ↓
lag / rolling 특징 생성
      ↓
시간순 모델 학습 및 평가
      ↓
분석 a1~a10
      ↓
Streamlit 대시보드 데이터 생성
      ↓
실행 결과 검증
```

## 주요 전처리

### 역명 표준화

역명 뒤에 붙은 괄호 형태의 부기명을 제거하여
동일 역이 서로 다른 역처럼 집계되는 문제를 방지했습니다.

팬데믹 회복률 분석에서는
표준화된 역명에 노선 정보를 결합하여
역을 구분했습니다.

### 비정상 이용량 처리

`total <= 0`인 값을 발견했을 때
행 전체를 삭제하지 않고 해당 값만 결측 처리했습니다.

같은 날짜와 역에 존재하는
다른 정상 승하차 정보를 보존하기 위한 처리입니다.

### 강우와 총강수 구분

총강수량에는 눈이 포함될 수 있기 때문에
비 효과 분석에는 `precip_mm`이 아니라
강우량인 `rain_mm`을 사용했습니다.

강우 여부는 일 강우량 1mm 이상을 기준으로 정의했습니다.

강우 강도별 분석에서는 0mm를 기준으로
0~5mm, 5~20mm, 20mm 초과 구간을 비교했습니다.

### 데이터 중복 처리

지하철 원본 데이터 1,319,521행을 승차·하차별로 분리한
2,639,042행 중 고유 키가 중복된 초과 행은 372행이었습니다.

고유 키는 `(date, line, station, io_type)`을 사용했으며,
SQLite 적재 과정에서는 `INSERT OR IGNORE` 정책을 유지했습니다.

검증 결과 372개 중복 그룹 모두 동일 키에 서로 다른
이용량이 기록되어 있었으며, 필수 키 결측은 없었습니다.

중복으로 제외된 행의 이용량 합계는 230,226건으로,
원본 전체 이용량의 약 0.000829%에 해당했습니다.

다만 이 값이 모두 실제 누락 수요라는 의미는 아닙니다.
원본 데이터만으로 중복 레코드의 집계 의미를 확정할 수 없어
기존 적재 정책을 유지하고 그 한계를 문서화했습니다.

## 모델링

수요 예측에는 `RandomForestRegressor`를 사용했습니다.

모델에는 날씨와 달력 정보뿐 아니라
과거 수요를 나타내는 lag 및 rolling 특징을 사용했습니다.

시계열 데이터에서는 미래 정보가
학습 과정에 들어가지 않도록 하는 것이 중요하기 때문에
시간 순서를 유지하여 학습과 테스트 데이터를 분리했습니다.

### 기본 모델 성능

| 평가 지표 | 결과 |
|---|---:|
| MAE | 347,269건 |
| MAPE | 2.99% |
| R² | 0.9649 |

이 결과는 시간순 테스트 구간에서 평가한 값입니다.

다만 실측 날씨와 과거 실측 이용량을 사용하므로,
실제 예보 날씨만으로 여러 미래 날짜를 예측하는
운영 환경의 성능과는 구분해야 합니다.

## 날씨 변수의 예측 기여도

날씨 변수가 실제로 예측 성능에 기여하는지 확인하기 위해
날씨 포함 모델과 날씨 제외 모델을 동일한 조건에서 비교했습니다.

### 전체 테스트 구간

| 평가 지표 | 날씨 포함 | 날씨 제외 |
|---|---:|---:|
| MAE | 347,269건 | 377,241건 |
| MAPE | 2.99% | 3.19% |
| R² | 0.9649 | 0.9615 |

날씨 변수를 포함했을 때 MAPE가 **0.20%p 개선**되었습니다.

### 집중호우 구간

일 강우량 30mm 이상인 25일을 별도로 평가했습니다.

| 모델 | MAPE |
|---|---:|
| 날씨 포함 | 4.32% |
| 날씨 제외 | 6.25% |

집중호우 구간에서는 날씨 변수를 포함한 모델의
MAPE가 **1.93%p 낮게** 나타났습니다.

### Walk-forward 검증

5개 검증 구간 중 3개 구간에서
날씨 변수가 예측 성능을 개선했습니다.

그러나 구간별 MAPE 개선 폭의 단순 평균은
-0.02%p로 나타났습니다.

따라서 날씨 변수는 전체 테스트 구간과 집중호우 구간에서
성능 개선에 기여했지만,
모든 시기에 일관된 개선 효과를 보이지는 않았습니다.

### Permutation importance

기본 모델의 특징 중요도 외에도
Permutation importance를 이용하여
특징을 섞었을 때 모델의 예측 성능이
얼마나 달라지는지 분석했습니다.

이를 통해 트리 모델의 기본 특징 중요도만으로
변수의 기여도를 판단하지 않도록 보완했습니다.

분석 결과는 다음 파일에 저장됩니다.

`models/weather_permutation_importance.csv`

Permutation importance 역시 특징 사이의 상관관계나
평가 데이터 구성에 영향을 받을 수 있으므로,
날씨 변수 제거 실험과 함께 해석해야 합니다.

## 강우와 지하철 이용량

### 단순 평균 비교

2019~2024년 전체 2,192일을 분석했습니다.

| 구분 | 날짜 수 | 평균 이용량 |
|---|---:|---:|
| 비 오는 날 | 604일 | 12,383,645건 |
| 비 오지 않는 날 | 1,588일 | 12,779,473건 |

비 오는 날의 평균 이용량은
비가 오지 않는 날보다 **3.10% 낮았습니다.**

하지만 단순 평균 차이에는
연도, 계절, 요일 구성의 영향이 포함될 수 있습니다.

### 연도·월·요일·공휴일 통제

연도·월·요일·공휴일 여부를 통제한 회귀분석에서는
비 오는 날의 이용량이 평균적으로 약 330,335건,
전체 일평균 대비 **2.61% 낮게** 나타났습니다.

HC1 강건 표준오차 기준 95% 신뢰구간은
-424,543건부터 -236,128건까지였습니다.

이 결과는 강우와 이용량 사이의 조건부 연관성을 나타내며,
인과관계를 입증하지는 않습니다.

### 평일 기준 연도·월 보정 분석

주말과 공휴일의 영향을 줄이기 위해
평일·비공휴일 1,487일을 대상으로 추가 분석했습니다.

각 날짜의 이용량을 같은 연도·월의 평일 평균으로 보정한 뒤
강우일과 비강우일의 상대 이용량을 비교했습니다.

| 항목 | 결과 |
|---|---:|
| 분석 날짜 | 1,487일 |
| 강우일 | 409일 |
| 비강우일 | 1,078일 |
| 보정 후 차이 | -1.41%p |
| 95% 신뢰구간 | -2.02 ~ -0.86%p |

신뢰구간은 연도·월 단위 클러스터 부트스트랩으로 계산했습니다.

### 강우 강도별 분석

0mm인 날을 기준으로 강우 강도별 상대 이용량을 비교했습니다.

| 강우량 | 날짜 수 | 상대 이용량 차이 | 95% 신뢰구간 |
|---|---:|---:|---|
| 0mm | 866일 | 기준 | - |
| 0~5mm | 401일 | -0.17%p | -0.75 ~ +0.36%p |
| 5~20mm | 134일 | -1.87%p | -2.54 ~ -1.21%p |
| 20mm 초과 | 86일 | -4.01%p | -5.71 ~ -2.44%p |

0~5mm 구간은 0mm를 제외한 강우일을 의미합니다.

소량 강우 구간에서는 이용량 차이가 뚜렷하지 않았지만,
강우량이 많은 구간에서는 상대 이용량이 더 낮게 나타났습니다.

특히 20mm 초과 강우일의 상대 이용량은
0mm인 날보다 **4.01%p 낮았습니다.**

강우 여부 비교는 1mm 이상을 강우일로 정의하고,
강우 강도별 비교는 0mm 초과부터 구분하므로
두 분석의 날짜 수는 서로 다릅니다.

관측된 결과는 강우와 이용량 사이의 연관성을 나타내며,
강우가 이용량 감소를 직접 유발했다는 의미는 아닙니다.

## 시계열 검증

무작위 분할만으로 모델을 평가하면
미래와 가까운 데이터가 학습 데이터에 포함되어
실제보다 좋은 성능이 나타날 수 있습니다.

이를 확인하기 위해 다음 평가 방식을 비교했습니다.

- 무작위 분할
- 시간순 분할
- Walk-forward 검증
- 동일 테스트 기간을 고정한 학습 데이터 구성 비교

### 기존 무작위 분할과 시간순 분할

기존 실험에서는 무작위 분할과 시간순 분할의
테스트 날짜가 서로 달랐습니다.

따라서 두 모델의 성능 차이를
데이터 분할 방식만의 영향으로 해석하기는 어렵습니다.

### 동일 테스트 기간 비교

2022년 전체 365일을 테스트 기간으로 고정하고
두 모델의 학습 데이터 개수를 1,089일로 통일했습니다.

시간순 모델은 2022년 이전 데이터만 사용했습니다.

혼합 학습 모델은 2022년 테스트 기간을 제외한
과거·미래 데이터에서 학습 날짜를 무작위로 선택했으며,
이 중 431일은 테스트 기간 이후의 데이터였습니다.

| 항목 | 시간순 학습 | 과거·미래 혼합 학습 |
|---|---:|---:|
| 학습 데이터 | 1,089일 | 1,089일 |
| 테스트 데이터 | 2022년 365일 | 2022년 365일 |
| 테스트 이후 학습 데이터 | 없음 | 431일 |
| MAE | 645,482건 | 341,334건 |
| MAPE | 5.43% | 3.32% |
| R² | 0.9174 | 0.9737 |

혼합 학습 모델의 MAPE가 **2.11%p 낮았습니다.**

하지만 혼합 학습에는 2022년을 예측하는 데
사용할 수 없는 미래 시점의 데이터가 포함되어 있습니다.

따라서 혼합 학습의 성능을 실제 미래 예측 성능으로
해석할 수는 없습니다.

또한 두 학습셋은 시간적 분포가 다르므로
성능 차이 전체를 데이터 누수의 독립적인 효과로
단정할 수는 없습니다.

### Walk-forward 검증

Walk-forward 검증에서는
과거 데이터로 학습한 뒤 그다음 시기를 평가하도록 하여
시점별 성능 변화를 확인했습니다.

특히 2019년으로 학습하고
2020년을 예측하는 구간에서
성능이 크게 저하되었습니다.

이는 팬데믹처럼 학습 데이터에 존재하지 않던
구조 변화가 발생하면 예측 성능이 저하될 수 있음을 보여줍니다.

## 팬데믹 구조 변화

시간순 검증에서 2019년으로 학습하고
2020년을 예측하는 구간의 성능이 크게 저하되었습니다.

추가 분석 결과, 2020년에는
지하철 이용량 자체가 급격하게 감소했습니다.

2020년 일평균 이용량은
2019년 대비 약 **27.7% 감소**했습니다.

이후 이용량은 점차 회복했지만
2024년에도 2019년보다 약 **7.2% 낮았습니다.**

또한 팬데믹 급성기에는
주말 수요가 평일보다 상대적으로 더 크게 감소했습니다.

이 문제는 단순한 모델 성능 저하가 아니라
팬데믹으로 인해 기존 수요 패턴이 달라진
구조 변화와 연결하여 해석할 필요가 있었습니다.

따라서 팬데믹 이전, 급성기, 회복기,
엔데믹 이후의 수요 변화를 추가로 분석하고
팬데믹 국면 정보를 모델 특징에도 반영했습니다.

### 고정 역 집합 기준 회복률 검증

연도별 역 구성의 차이가 팬데믹 회복률에
영향을 줄 수 있다는 점을 고려하여
2019~2024년 동안 관측된 역 중
일정한 데이터 커버리지 조건을 만족하는 역을
고정한 뒤 회복률을 다시 계산했습니다.

역은 **노선 + 표준화 역명**을 기준으로 구분했습니다.

기본 분석에서는 연도별 데이터 커버리지
95% 이상인 역 576개를 사용했습니다.

| 비교 기준 | 2024년 이용량의 2019년 대비 변화 |
|---|---:|
| 전체 역 기준 | -7.22% |
| 고정 역 576개 기준 | -7.84% |
| 고정 역 - 전체 역 | -0.62%p |

고정 역 기준에서도 2024년 이용량은
2019년 수준을 회복하지 못했습니다.

### 커버리지 임계값 민감도 분석

| 최소 커버리지 | 고정 역 수 | 2024년 변화율 |
|---|---:|---:|
| 90% | 576개 | -7.84% |
| 95% | 576개 | -7.84% |
| 100% | 572개 | -7.84% |

표의 수치는 소수점 둘째 자리로 반올림했습니다.

임계값을 변경해도 2024년 회복률의
방향과 크기는 거의 달라지지 않았습니다.

따라서 전체 역 구성의 변화만으로
팬데믹 이후 이용량 감소를 설명하기는 어렵습니다.

분석 결과는 다음 파일에 저장됩니다.

`models/pandemic_station_fixed_results.json`

## 휴일 피처 보강 실험

기존 모델의 휴일 관련 예측 오차를 확인한 뒤
다음 세 가지 특징을 추가하여 성능을 비교했습니다.

- `is_labor_day`: 근로자의 날 여부
- `is_day_after_holiday`: 공휴일 다음 날 여부
- `holiday_streak_length`: 연속 휴일 길이

기존 모델과 새 모델은 동일한 시간순
학습·테스트 구간에서 비교했습니다.

| 평가 지표 | 기존 모델 | 휴일 피처 추가 모델 |
|---|---:|---:|
| 특징 수 | 25개 | 28개 |
| MAE | 347,269건 | 337,831건 |
| MAPE | 2.99% | 2.89% |
| R² | 0.9649 | 0.9707 |

휴일 피처를 추가했을 때
MAPE가 **0.10%p 개선**되었습니다.

### 날짜 유형별 성능

| 날짜 유형 | 기존 MAPE | 추가 모델 MAPE |
|---|---:|---:|
| 평일 | 1.95% | 1.90% |
| 주말 | 3.61% | 3.50% |
| 공휴일 | 13.60% | 12.87% |
| 근로자의 날 | 43.08% | 16.87% |
| 공휴일 다음 날 | 4.13% | 4.10% |

특히 테스트 구간에 포함된
2024년 5월 1일 근로자의 날의 예측 오차는
43.08%에서 16.87%로 감소했습니다.

다만 테스트 구간에서 근로자의 날은
1일만 평가되었으므로,
이 결과만으로 다른 연도에서도
동일한 개선 효과가 나타난다고 볼 수는 없습니다.

또한 휴일 피처 추가 모델이 모든 시기에서
일관되게 우수한지에 대한 추가 검증이 필요합니다.

따라서 기본 모델을 즉시 교체하지 않고,
별도의 비교 실험 결과로 관리했습니다.

분석 결과는 다음 파일에 저장됩니다.

- `models/holiday_feature_comparison.json`
- `models/holiday_feature_importance.csv`
- `models/holiday_feature_predictions.csv`

## Streamlit 대시보드

대시보드에서는 분석 결과를
다음과 같은 메뉴로 구분하여 확인할 수 있습니다.

| 메뉴 | 주요 내용 |
|---|---|
| 프로젝트 개요 | 데이터 범위 및 프로젝트 소개 |
| 이용 패턴 | 날짜별 이용량과 기본 수요 패턴 |
| 날씨 영향 | 날씨·강우 분석, a7 통제 회귀, a9 강우 강도별 보정 결과 |
| 팬데믹 변화 | 팬데믹 시기별 수요 변화 및 a10 고정 역 비교 |
| 수요 예측 | 모델 예측값과 실제 이용량 비교 |
| 직접 예측해보기 | 기존 모델을 활용한 날씨 조건별 수요 예측 시나리오 |
| 모델 분석 | 특징 중요도, 시계열 검증, a6 날씨 변수 제거 실험 |

### 직접 예측 기능

대시보드의 `직접 예측해보기` 메뉴에서는
사용자가 날씨 조건을 조절하여
기존 Random Forest 모델의 예측 결과가
어떻게 달라지는지 확인할 수 있습니다.

이 기능은 모델에 입력되는 날씨 조건을 변경하여
예측값의 변화를 비교하는 시나리오 실험입니다.

모델에는 과거 실측 수요를 기반으로 생성한
lag 및 rolling 특징이 포함되어 있으므로,
과거 수요 정보가 없는 임의의 미래 날짜를
독립적으로 예측하는 기능은 아닙니다.

직접 예측 화면은 `dashboard/predict_tab.py`에 구현하고,
`dashboard/app.py`에서 호출하도록 구성했습니다.

기존 대시보드의 분석 화면을 유지하면서
a6·a7·a9·a10 결과를 추가했습니다.

추가 분석 화면은
`dashboard/analysis_extensions.py`에 구현하고,
`dashboard/app.py`에서 호출하도록 구성했습니다.

대시보드의 수치는
`models/`에 저장된 분석 결과를 기반으로 표시합니다.

다만 모든 화면의 표시 수치와 JSON 결과를
자동으로 비교하는 검증은 아직 추가하지 않았습니다.

## 실행 방법

### 1. 의존성 설치

프로젝트 최상위 폴더에서 실행합니다.

```powershell
python -m pip install -r requirements.txt
```

### 2. 실행 전 파일 검증

```powershell
python verify_code.py
```

프로젝트 핵심 소스 파일이 존재하는지 확인합니다.

이 단계에서는 아직 생성되지 않았을 수 있는
원본 데이터와 모델 산출물 검사를 생략합니다.

### 3. 전체 파이프라인 실행

```powershell
python run_all.py
```

`run_all.py`는 다음 15개 단계를 순서대로 실행합니다.

1. 원본 데이터 준비 및 기존 CSV 검증
2. SQLite DB 구축
3. 모델 학습 및 평가
4. EDA
5. 강우 영향 분석
6. 데이터 누수 및 시계열 검증
7. 전처리 검증
8. 팬데믹 구조 변화 분석
9. 날씨 변수 기여도 및 Walk-forward 검증(a6)
10. 강우 효과 보정 분석(a7)
11. 동일 테스트 기간 데이터 분할 비교(a8)
12. 평일 기준 강우 효과 보정 분석(a9)
13. 고정 역 집합 기준 팬데믹 회복률 검증(a10)
14. 대시보드 데이터 생성
15. 전체 실행 결과 검증

a6~a10은 전체 파이프라인에 포함되어 있으므로
정상적으로 전체 실행했다면 별도로 실행할 필요가 없습니다.

각 단계에서 오류가 발생하면 실행을 중단하도록 구성했습니다.

### 4. 오프라인 실행 시 주의사항

기존 원본 지하철 CSV가 모두 존재하면
다운로드 없이 파일을 검증한 뒤 재사용합니다.

원본 파일 검증에 실패하면
불완전한 데이터를 그대로 사용하지 않고 실행을 중단합니다.

반대로 필요한 원본 파일이 없다면
다운로드 또는 날씨 수집 과정에서
인터넷 연결이 필요할 수 있습니다.

`run_all.py`에는 별도의 `--offline` 옵션이 없으므로
임의로 추가해서 실행하지 않습니다.

### 5. 코드 및 산출물 검증

실행 전 핵심 파일 확인:

```powershell
python verify_code.py
```

전체 실행 후 원본 데이터와 산출물 확인:

```powershell
python verify_code.py --after-run
```

`--after-run` 검증에서는 다음 항목을 확인합니다.

- 핵심 프로젝트 소스 파일
- 2019~2024년 지하철 원본 CSV 및 날씨 CSV
- SQLite DB
- 기본 모델 성능 및 예측 결과
- 시계열 검증 결과
- a6~a10 분석 JSON 및 CSV
- 휴일 피처 비교 결과
- 대시보드 데이터 CSV

JSON 결과는 주요 필수 항목이
누락되지 않았는지도 확인합니다.

단, 현재 검증은 파일 존재 여부와
주요 JSON 구조 확인을 중심으로 하며,
DB 내부 모든 레코드와
Streamlit 화면의 표시 수치를 자동 대조하지는 않습니다.

### 6. 대시보드 실행

```powershell
streamlit run dashboard/app.py
```

### 7. 개별 분석 실행

필요한 분석만 다시 실행하려면
다음과 같이 해당 스크립트를 실행할 수 있습니다.

```powershell
python analysis/a6_weather_ablation.py
python analysis/a7_rain_adjusted.py
python analysis/a8_fixed_test_split.py
python analysis/a9_rain_workday_adjusted.py
python analysis/a10_pandemic_station_fixed.py
```

각 분석 결과는 `models/`에
JSON 또는 CSV로 저장됩니다.

데이터 준비, DB 구축, 모델 학습,

최신 `verify_code.py`에서는
a10 JSON, 대시보드 확장 모듈,
휴일 피처 산출물도 검증 대상에 포함했습니다.

로컬 환경에서 실행한 결과,
기본 검증과 `--after-run` 검증이 모두 통과했습니다.

다만 새로운 가상환경에서 의존성을 처음부터 설치하고
전체 과정을 실행하는 검증은 별도로 수행할 예정입니다.

## 주요 분석 결과

이번 프로젝트에서 확인한 핵심 결과는 다음과 같습니다.

- 날씨 변수 포함 모델은 전체 테스트 구간에서 MAPE를 0.20%p 개선했습니다.
- 집중호우 구간에서는 날씨 변수 포함 모델의 MAPE가 1.93%p 낮았습니다.
- Walk-forward 5개 구간 중 3개 구간에서 날씨 변수 추가가 성능을 개선했지만, 평균 개선 폭은 -0.02%p였습니다.
- 평일 기준 연도·월 보정 후 강우일의 상대 이용량은 비강우일보다 1.41%p 낮았습니다.
- 일 강우량 20mm 초과 구간에서는 상대 이용량이 4.01%p 낮았습니다.
- 동일한 2022년 테스트 기간에서 과거·미래 혼합 학습의 MAPE가 2.11%p 낮았지만, 미래 데이터가 포함되어 실제 예측 성능으로 해석할 수 없습니다.
- 2024년 이용량은 2019년 대비 전체 역 기준 7.22%, 고정 역 기준 7.84% 낮았습니다.
- 휴일 피처를 추가한 실험에서 MAPE가 2.99%에서 2.89%로 개선됐지만, 추가 시기 검증이 필요합니다.

이 결과는 날씨와 과거 수요뿐 아니라
학습·평가 시점, 휴일 특성,
분석 대상 역의 구성과 외부 구조 변화도
모델 성능을 해석하는 데 중요하다는 점을 보여줍니다.

## 이 프로젝트에서 중점적으로 다룬 문제

이 프로젝트에서는 모델의 점수만 높이는 것보다
다음 문제를 직접 확인하는 데 중점을 두었습니다.

- 원본 데이터의 품질 문제를 실제 값으로 검증
- 눈과 비를 구분하여 강우 변수 정의
- 연도·월·요일 등 교란 요인을 고려한 강우 분석
- 강우 강도별 신뢰구간을 통한 불확실성 확인
- 날씨 변수 제거 실험을 통한 예측 기여도 검증
- Permutation importance를 통한 특징 중요도 보완
- 시계열 데이터의 미래 정보 누수 방지
- 동일 테스트 기간에서 학습 데이터 구성의 영향 확인
- Walk-forward를 이용한 시점별 성능 검증
- 팬데믹과 같은 구조 변화의 영향 분석
- 고정 역 집합과 커버리지 민감도 분석
- 휴일 관련 특징 추가 및 성능 비교
- 특정 구간의 성능 저하 원인을 데이터에서 추적
- 전체 파이프라인과 DB 재구축 결과 검증
- 분석 JSON을 활용한 대시보드 확장
- 날씨 조건을 조절하는 수요 예측 시나리오 기능 구현
- GitHub Pages를 통한 포트폴리오 웹페이지 배포

## 한계

현재 데이터는 서울·수도권의 여러 철도 노선을 포함하지만
수도권 전철 전체를 완전히 포함하지는 않습니다.

강우 분석은 관측 자료에서 나타난 연관성을 분석한 것으로,
강우가 이용량 변화를 직접 유발했다는
인과적 증거로 해석할 수 없습니다.

모델은 실측 날씨 데이터를 사용하므로
실제 기상 예보를 입력하는 환경과
예측 성능에 차이가 발생할 수 있습니다.

lag 및 rolling 특징은 과거 실측 이용량을 사용하므로
직전 날짜의 실측값이 순차적으로 확보되는
일별 예측 상황을 전제로 합니다.

따라서 대시보드의 직접 예측 기능도
과거 수요 정보가 확보된 조건에서
날씨 변화에 따른 예측값을 비교하는 용도로 해석해야 합니다.

또한 팬데믹, 대규모 행사, 교통 정책 변화,
운행 장애처럼 갑작스럽게 발생하는 외부 요인은
과거 수요와 날씨만으로 완전히 예측하기 어렵습니다.

고정 역 분석은 역 구성 변화의 영향을 점검하기 위한 것이며,
역별 이용 행태나 노선 운영 변화 등
모든 외부 요인을 통제한 분석은 아닙니다.

휴일 피처 추가 실험은 동일한 테스트 구간에서
성능 개선을 보였지만,
다른 연도와 구조 변화 구간에서도
안정적인 개선이 나타나는지 확인해야 합니다.

현재 자동 검증은 주요 파일과 JSON 구조를 확인하지만,
모든 분석 지표의 값 범위와
대시보드 화면의 수치 일치 여부까지
완전히 검증하지는 않습니다.

향후 예보 기상 데이터와 외부 이벤트 정보를 추가하고
새로운 시점의 데이터에 대한 검증을 강화하면
실제 운영 환경에 가까운 수요 예측 모델로 발전시킬 수 있습니다.

상세 분석 내용은
[분석 보고서](reports/analysis_report.md)에서 확인할 수 있습니다.
