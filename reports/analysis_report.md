# 서울 지하철 수요와 날씨 영향 분석

## 1. 분석 목적

서울·수도권 철도 승하차 이용량과 서울의 일별 날씨 데이터를 결합하여 날씨와 지하철 수요 사이의 관계를 분석하고, 시간 순서를 고려한 예측 모델의 성능과 한계를 검증했다.

단순한 상관관계 확인에 그치지 않고 강우 효과의 교란 요인, 날씨 변수의 예측 기여도, 학습 데이터의 시간적 구성, 팬데믹에 따른 수요 구조 변화까지 함께 분석했다.

주요 분석 질문은 다음과 같다.

- 지하철 이용량은 날짜와 요일에 따라 어떤 패턴을 보이는가?
- 비가 오는 날의 이용량은 실제로 달라지는가?
- 요일과 시기적 요인을 보정한 후에도 강우와 이용량 사이의 연관성이 나타나는가?
- 날씨 정보를 추가하면 수요 예측 성능이 개선되는가?
- 시간 순서를 무시한 데이터 분할은 모델 평가에 어떤 영향을 주는가?
- 팬데믹과 같은 구조 변화는 수요와 예측 성능에 어떤 영향을 주는가?
- 근로자의 날과 연속 휴일 정보를 추가하면 예측 오차를 줄일 수 있는가?

## 2. 데이터와 전처리

### 2.1 분석 데이터

2019년 1월 1일부터 2024년 12월 31일까지의 지하철 일별 승하차 이용량과 서울의 일별 기상 데이터를 사용했다.

| 항목 | 규모 |
|---|---:|
| 수집된 철도 노선 | 27개 |
| 원본 지하철 데이터 | 1,319,521행 |
| SQLite 적재 데이터 | 2,638,670행 |
| 일별 통합 데이터 | 2,192일 |
| 모델링 데이터 | 2,185일 |

지하철 데이터는 날짜를 기준으로 일 단위 집계하고 날씨 데이터와 결합하여 분석용 데이터를 구성했다.

승차와 하차를 합산한 값이므로 이용량 단위는 고유 이용자 수를 의미하는 '명'이 아니라 '건'으로 표기했다.

현재 데이터에는 서울·수도권의 여러 철도 노선이 포함되지만, 수도권 전철 전체를 완전히 포함하지는 않는다.

### 2.2 역명 표준화

역명 뒤에 붙은 괄호 형태의 부기명을 제거하여 동일 역이 서로 다른 이름으로 집계되는 문제를 줄였다.

### 2.3 비정상 이용량 처리

이용량이 0 이하인 값은 해당 행 전체를 삭제하지 않고 문제가 있는 이용량 값만 결측 처리했다.

이는 같은 행에 존재하는 다른 정상 정보를 보존하기 위한 처리다.

### 2.4 강우와 총강수 구분

총강수량에는 눈과 같은 강수 형태가 포함될 수 있으므로 강우 효과 분석에는 `precip_mm`이 아니라 `rain_mm`을 사용했다.

강우 여부는 `rain_mm >= 1.0`을 기준으로 정의했다.

강우 강도별 분석에서는 0mm를 기준으로 0~5mm, 5~20mm, 20mm 초과 구간을 비교했다.

### 2.5 데이터 적재 및 재현성

2019~2024년 지하철 원본 CSV 1,319,521행을 승차·하차별로 분리한 결과 총 2,639,042행이 생성되었다.

SQLite 적재 과정에서는 `(date, line, station, io_type)`을 고유 키로 사용하고, `INSERT OR IGNORE`를 통해 동일 키의 중복 저장을 방지했다.

강사 피드백에서 지적된 372행의 제외 원인을 확인하기 위해 원본 데이터의 고유 키 중복 여부와 필수 키 결측 여부를 검증했다.

| 검증 항목 | 결과 |
|---|---:|
| 승차·하차 분리 후 전체 데이터 | 2,639,042행 |
| 고유 키 기준 중복 초과 행 | 372행 |
| 중복 그룹에 속한 전체 행 | 744행 |
| 필수 키 결측·공백 행 | 0행 |
| 원본 고유 키 개수 | 2,638,670개 |
| 빈 SQLite DB 적재 결과 | 2,638,670행 |

검증 결과, 최초 적재 과정에서 제외된 372행은 모두 원본 데이터 내부의 고유 키 중복에 해당했으며, 필수 키 결측으로 인해 제외된 행은 없었다.

별도의 빈 SQLite DB에 데이터를 적재하여 원본 고유 키 개수와 실제 적재 행 수가 일치하는 것도 확인했다.

또한 DB에 저장된 이용량 합계가 중복 제외 후 계산한 이용량 합계와 일치하는지 검증했다.

전체 파이프라인과 코드 검증을 실행하여 주요 단계가 정상 완료되는 것을 확인했다.

다만 새로운 가상환경에서 의존성을 처음부터 설치하고 전체 파이프라인을 실행하는 검증은 아직 수행하지 않았다.

### 2.6 중복 데이터 영향도 분석

고유 키가 중복된 372개 그룹을 추가 분석한 결과, 모든 그룹에서 동일 키에 서로 다른 이용량이 기록되어 있었다.

따라서 해당 데이터를 단순히 값까지 동일한 중복 레코드로 간주할 수는 없었다.

중복으로 제외된 행의 이용량 분포와 발생 위치를 확인하고, 기존 `INSERT OR IGNORE` 정책이 전체 이용량에 미치는 영향을 정량적으로 분석했다.

#### 2.6.1 중복 발생 특성

| 항목 | 결과 |
|---|---:|
| 중복 초과 행 | 372행 |
| 이용량이 서로 다른 중복 키 그룹 | 372개 |
| 중복 그룹의 등록일자가 모두 같은 경우 | 372개 |
| 등록일자가 서로 다른 그룹 | 0개 |
| 중복 발생 기간 | 2019~2021년 |
| 중복 발생 노선 | 경의선 |

중복은 2019~2021년에 발생했으며, 모두 경의선의 일부 역에 집중되어 있었다.

연도별 중복 발생 현황은 다음과 같다.

| 연도 | 중복 초과 행 | 제외 이용량 |
|---|---:|---:|
| 2019 | 250행 | 93,525건 |
| 2020 | 68행 | 67,663건 |
| 2021 | 54행 | 69,038건 |
| 합계 | 372행 | 230,226건 |

역별 중복 발생 현황은 다음과 같다.

| 노선 | 역 | 중복 초과 행 | 제외 이용량 |
|---|---|---:|---:|
| 경의선 | 서울역 | 304행 | 196,338건 |
| 경의선 | 홍대입구 | 32행 | 7,028건 |
| 경의선 | 디지털미디어시티 | 26행 | 17,958건 |
| 경의선 | 공덕 | 10행 | 8,902건 |
| 합계 | | 372행 | 230,226건 |

전체 중복 초과 행 중 서울역에서 발생한 중복이 304행으로 가장 많았으며, 제외 이용량도 196,338건으로 가장 컸다.

승차와 하차의 중복 초과 행은 각각 186행으로 동일했으나, 제외 이용량은 승차 105,108건, 하차 125,118건으로 차이가 있었다.

또한 372개 중복 그룹 모두 등록일자가 동일했다. 다만 등록일자가 같다는 사실만으로 중복 레코드의 발생 원인이나 집계 방식까지 확정할 수는 없다.

#### 2.6.2 제외 이용량의 분포

기존 `INSERT OR IGNORE` 정책에 따라 저장되지 않는 행의 이용량 분포는 다음과 같다.

| 제외 이용량 범위 | 행 수 | 비율 |
|---|---:|---:|
| 0~2건 | 255행 | 68.55% |
| 3~10건 | 9행 | 2.42% |
| 11~100건 | 19행 | 5.11% |
| 101~1,000건 | 28행 | 7.53% |
| 1,001건 이상 | 61행 | 16.40% |
| 합계 | 372행 | 100.00% |

제외된 행의 이용량 중앙값은 1건, 평균은 약 618.89건, 최댓값은 6,596건이었다.

전체 제외 행의 68.55%는 이용량이 0~2건으로 작았지만, 16.40%는 1,001건 이상이었다.

따라서 중복으로 제외된 데이터가 모두 소규모 이용량에 해당하는 것은 아니었다.

#### 2.6.3 전체 이용량에 대한 영향

기존 중복 처리 정책에 따라 제외되는 이용량의 규모를 확인했다.

| 항목 | 결과 |
|---|---:|
| 원본 전체 이용량 | 27,773,755,430건 |
| 중복 제외 후 이용량 | 27,773,525,204건 |
| 제외된 행의 이용량 합계 | 230,226건 |
| 원본 전체 이용량 대비 제외 비율 | 0.000829% |

중복으로 제외된 행의 이용량 합계는 230,226건으로, 2019~2024년 원본 전체 이용량의 약 0.000829%에 해당했다.

전체 이용량 기준으로는 비중이 매우 작았지만, 중복이 경의선의 특정 역에 집중되어 있으므로 개별 역이나 날짜 단위 분석에서는 상대적으로 큰 영향을 미칠 가능성이 있다.

또한 제외된 230,226건이 모두 실제 누락 수요라는 의미는 아니다. 원본 데이터만으로 동일 키에 기록된 서로 다른 이용량이 중복 집계인지 별도 집계인지 확정할 수 없기 때문이다.

#### 2.6.4 중복 처리 정책

이번 프로젝트에서는 기존 SQLite의 `INSERT OR IGNORE` 정책을 유지했다.

동일한 고유 키가 여러 번 등장하면 최초로 입력된 행을 저장하고 이후 중복되는 행은 제외하는 방식이다.

이 정책을 유지한 이유는 다음과 같다.

- 원본 데이터만으로 중복 레코드의 발생 원인과 집계 의미를 확정할 수 없다.
- 서로 다른 이용량을 무조건 합산하면 실제보다 수요가 과대 집계될 가능성이 있다.
- 반대로 중복을 제외하면 일부 실제 이용량이 누락될 가능성도 있다.
- 현재 정책에 따른 제외 이용량은 전체 이용량의 약 0.000829%이며, 그 규모와 발생 위치를 검증했다.
- 기존 DB 적재 결과와 중복 제외 후 예상 이용량 합계가 일치함을 확인했다.

따라서 근거가 불충분한 상태에서 임의로 이용량을 합산하거나 고유 키 구조를 변경하지 않았다.

대신 중복 발생 규모, 연도·노선·역별 분포, 제외 이용량과 처리 한계를 명시하여 데이터 품질 검증 과정과 결과를 재현할 수 있도록 했다.

## 3. 기본 수요 패턴

지하철 이용량을 날짜와 요일 기준으로 확인하여 수요의 기본적인 시간 패턴을 분석했다.

평일과 주말 사이에는 이용량 차이가 존재했으며, 요일에 따라 반복되는 수요 패턴도 나타났다.

따라서 지하철 수요를 분석하거나 예측할 때 날씨 변수만 사용하는 것은 충분하지 않으며, 요일과 휴일 같은 달력 정보도 함께 고려해야 한다고 판단했다.

예측 모델에도 요일, 월, 주말·공휴일·평일 여부 등의 특징을 포함했다.

추가로 근로자의 날, 휴일 다음 날, 연속 휴일 길이를 나타내는 피처를 생성하여 기존 달력 정보만으로 설명하기 어려웠던 특수 날짜의 수요 패턴을 모델에 반영할 수 있도록 했다.

## 4. 비와 지하철 이용량

### 4.1 단순 평균 비교

2019~2024년 전체 2,192일을 대상으로 강우일과 비강우일의 이용량을 비교했다.

| 구분 | 날짜 수 | 평균 이용량 |
|---|---:|---:|
| 강우일 | 604일 | 12,383,645건 |
| 비강우일 | 1,588일 | 12,779,473건 |

강우일의 평균 이용량은 비강우일보다 약 395,828건, 3.10% 낮았다.

그러나 평일과 주말은 기본적인 수요 수준부터 다르며 연도와 계절에 따라서도 이용량이 달라진다.

따라서 단순 평균 차이를 강우 자체의 영향으로 해석하지 않았다.

### 4.2 동일 연도·월·요일 비교

연도·월·요일 조건이 같은 그룹 안에서 강우일과 비강우일의 이용량을 비교했다.

| 항목 | 결과 |
|---|---:|
| 비교 가능한 그룹 | 324개 |
| 비교에 포함된 강우일 | 559일 |
| 가중 평균 이용량 차이 | -347,015건 |
| 상대 이용량 차이 | -2.05% |

조건을 맞춘 비교에서도 강우일의 이용량이 더 낮게 나타났다.

### 4.3 통제 회귀분석

연도·월·요일·공휴일 여부를 통제한 회귀분석을 수행했다.

| 항목 | 결과 |
|---|---:|
| 분석 날짜 | 2,192일 |
| 강우일 회귀계수 | -330,335건 |
| 전체 일평균 대비 | -2.61% |
| HC1 강건 표준오차 | 48,065건 |
| 95% 신뢰구간 | -424,543 ~ -236,128건 |

해당 모형에서는 강우 여부와 이용량 사이에 음의 연관성이 나타났다.

다만 HC1 강건 표준오차는 시계열 자기상관을 직접 보정하지 않으므로, 통계적 유의성 해석에는 이러한 한계가 있다.

### 4.4 평일 기준 연도·월 보정 분석

요일과 공휴일 구성의 영향을 줄이기 위해 평일·비공휴일만을 대상으로 추가 분석했다.

각 날짜의 이용량을 같은 연도·월의 평일 평균으로 나누어 상대 이용량을 계산한 뒤 강우일과 비강우일을 비교했다.

분석 기간은 2019년 1월 2일부터 2024년 12월 31일까지이며, 총 1,487일과 72개의 연도·월 그룹이 포함되었다.

| 항목 | 결과 |
|---|---:|
| 분석 날짜 | 1,487일 |
| 강우일 | 409일 |
| 비강우일 | 1,078일 |
| 보정 후 상대 이용량 차이 | -1.41%p |
| 95% 신뢰구간 | -2.02 ~ -0.86%p |

95% 신뢰구간은 연도·월 단위 클러스터 부트스트랩으로 계산했다.

연도·월의 평균 수요 수준을 보정한 후에도 강우일의 상대 이용량이 낮게 나타났다.

### 4.5 강우 강도별 이용량 비교

0mm인 날을 기준으로 강우 강도별 상대 이용량을 비교했다.

| 강우량 | 날짜 수 | 상대 이용량 차이 | 95% 신뢰구간 |
|---|---:|---:|---|
| 0mm | 866일 | 기준 | - |
| 0~5mm | 401일 | -0.17%p | -0.75 ~ +0.36%p |
| 5~20mm | 134일 | -1.87%p | -2.54 ~ -1.21%p |
| 20mm 초과 | 86일 | -4.01%p | -5.71 ~ -2.44%p |

0~5mm 구간은 0mm를 제외한 강우일을 의미한다.

0~5mm 구간에서는 신뢰구간에 0이 포함되어 이용량 차이가 뚜렷하다고 보기 어려웠다.

반면 5~20mm와 20mm 초과 구간에서는 음의 차이가 관찰되었으며, 강우량이 많을수록 이용량 감소와의 연관성이 크게 나타났다.

강우 여부 분석은 1mm 이상을 강우일로 정의하지만, 강우 강도별 분석은 0mm 초과부터 구분하므로 집단별 날짜 수가 서로 다르다.

이러한 결과는 관측 자료에서 나타난 연관성으로, 강우가 이용량 감소를 직접 유발했다는 인과적 증거는 아니다.

## 5. 시간 순서를 고려한 모델 평가

### 5.1 예측 모델

일별 승하차 이용량 예측에 `RandomForestRegressor`를 사용했다.

모델에는 날씨 변수, 달력 변수, 팬데믹 국면 정보와 함께 이전 시점의 수요를 나타내는 lag 및 rolling 특징을 사용했다.

lag 및 rolling 특징은 과거 실측 이용량을 기반으로 계산하므로, 직전 날짜의 실제 이용량이 순차적으로 확보되는 일별 예측 상황을 전제로 한다.

### 5.2 기본 시간순 평가

시간 순서를 유지하여 학습 데이터와 테스트 데이터를 분리했다.

| 평가 지표 | 결과 |
|---|---:|
| MAE | 347,269건 |
| MAPE | 2.99% |
| R² | 0.9649 |

실측 기상 데이터를 사용한 평가 결과이므로 실제 예보 날씨를 입력하는 운영 환경의 성능과는 구분해야 한다.

이 결과는 휴일 보강 피처를 추가하기 전의 기존 모델 기준이다.

### 5.3 기존 무작위 분할과 시간순 분할

시계열 데이터를 무작위로 분할하면 미래와 가까운 데이터가 학습에 포함되어 실제보다 좋은 성능이 나타날 수 있다.

기존 실험에서는 무작위 분할과 시간순 분할을 비교했으나, 두 평가의 테스트 날짜가 달랐다.

따라서 기존 성능 차이를 데이터 분할 방식만의 영향으로 해석하기 어렵다는 한계를 확인했다.

### 5.4 동일 테스트 기간 비교

이 문제를 보완하기 위해 2022년 전체 365일을 동일한 테스트 기간으로 고정하고 학습 데이터의 구성을 달리하는 진단 실험을 수행했다.

두 모델 모두 1,089일을 학습에 사용했다.

- 시간순 학습: 2022년 이전 데이터만 사용
- 혼합 학습: 2022년을 제외한 과거·미래 데이터에서 무작위 추출

| 항목 | 시간순 학습 | 과거·미래 혼합 학습 |
|---|---:|---:|
| 학습 데이터 | 1,089일 | 1,089일 |
| 테스트 데이터 | 2022년 365일 | 2022년 365일 |
| 테스트 이후 학습 데이터 | 0일 | 431일 |
| MAE | 645,482건 | 341,334건 |
| MAPE | 5.43% | 3.32% |
| R² | 0.9174 | 0.9737 |

혼합 학습 모델의 MAPE가 시간순 학습 모델보다 2.11%p 낮게 나타났다.

그러나 혼합 학습에는 테스트 기간 이후의 데이터가 포함되어 있으므로 실제 미래 예측에 사용할 수 있는 평가 방식이 아니다.

또한 두 학습셋의 시간적 분포가 다르기 때문에 관측된 성능 차이 전체를 데이터 누수의 독립적인 효과로 해석할 수는 없다.

이 실험은 학습 데이터의 시간적 구성이 모델 평가 결과에 미치는 영향을 확인하기 위한 진단 실험이다.

### 5.5 Walk-forward 검증

학습 구간을 시간순으로 확장하면서 이후 기간을 평가하는 walk-forward 검증을 수행했다.

평가 시점에 따라 모델 성능이 크게 달라졌으며, 특히 2019년 데이터로 학습하고 2020년을 예측하는 구간에서 성능이 크게 저하되었다.

따라서 시계열 모델은 단일 분할의 성능만 확인하기보다 실제 예측 상황과 유사한 시간순 검증을 함께 수행해야 한다.

### 5.6 휴일 피처 보강 실험

기존 모델의 날짜별 예측 오차를 확인한 결과, 2024년 5월 1일 근로자의 날에 43.08%의 큰 오차가 발생했다.

기존 달력 피처는 요일, 주말, 공휴일, 평일 여부와 월 정보를 사용했으나, 근로자의 날이나 연속 휴일의 길이를 별도로 표현하지 못했다.

이 문제를 보완하기 위해 다음 세 가지 피처를 추가했다.

| 신규 피처 | 의미 |
|---|---|
| `is_labor_day` | 매년 5월 1일 근로자의 날 여부 |
| `is_day_after_holiday` | 바로 전날이 주말·공휴일·근로자의 날인지 여부 |
| `holiday_streak_length` | 주말·공휴일·근로자의 날이 연속되는 휴일 구간의 길이 |

근로자의 날은 기존 공휴일 목록에 포함하지 않고 별도 피처로 관리했다.

`is_day_after_holiday`는 데이터 행의 순서가 아닌 실제 날짜를 기준으로 계산했으며, `holiday_streak_length`는 일반 주말과 공휴일이 이어지는 경우도 포함한다.

기존 `is_holiday`와 `is_workday`의 정의는 변경하지 않았다.

#### 5.6.1 실험 조건

기존 모델과 휴일 보강 모델의 성능을 공정하게 비교하기 위해 동일한 학습 데이터와 테스트 데이터를 사용했다.

| 항목 | 실험 조건 |

| 예측 모델 | RandomForestRegressor |
| 학습 가능 데이터 | 2,185일 |

| 테스트 기간 | 2023-07-04 ~ 2024-12-31 |
| 데이터 분할 | 시간순 75:25 |
| 기존 피처 수 | 25개 |

두 모델은 휴일 피처 3개의 추가 여부만 다르며, 나머지 모델 설정과 학습·테스트 기간은 동일하게 유지했다.

기존 모델 결과를 보존하기 위해 비교 실험 결과는 별도의 파일에 저장했다.

#### 5.6.2 전체 예측 성능 비교

| 평가 지표 | 기존 모델 | 휴일 보강 모델 |
|---|---:|---:|
| MAE | 347,269.3건 | 337,830.5건 |

| MAPE | 2.99% | 2.89% |

휴일 피처를 추가한 모델은 기존 모델보다 MAE가 약 2.7%, RMSE가 약 8.7% 감소했다.

MAPE는 2.99%에서 2.89%로 0.10%p 낮아졌으며, R²는 0.9649에서 0.9707로 증가했다.

따라서 이번 테스트 기간에서는 신규 휴일 피처를 추가했을 때 전체 예측 성능이 개선되었다.

다만 하나의 테스트 기간에서 확인한 결과이므로 모든 연도에서도 같은 수준의 개선이 발생한다고 단정할 수는 없다.

#### 5.6.3 날짜 유형별 MAPE 비교

전체 MAPE만으로는 공휴일이나 근로자의 날처럼 특정 날짜에 집중된 예측 오차를 확인하기 어렵다.

이에 따라 테스트 기간을 평일, 주말, 공휴일, 근로자의 날, 휴일 다음 날로 구분하여 MAPE를 추가 계산했다.

| 날짜 유형 | 날짜 수 | 기존 MAPE | 보강 MAPE | 개선 폭 |
|---|---:|---:|---:|---:|
| 평일 | 368일 | 1.95% | 1.90% | +0.05%p |
| 주말 | 152일 | 3.61% | 3.50% | +0.11%p |
| 공휴일 | 27일 | 13.60% | 12.87% | +0.73%p |
| 근로자의 날 | 1일 | 43.08% | 16.87% | +26.21%p |
| 휴일 다음 날 | 180일 | 4.13% | 4.10% | +0.03%p |

평일, 주말, 공휴일은 공휴일을 우선 분류하는 방식으로 서로 겹치지 않도록 구분했다.

반면 근로자의 날과 휴일 다음 날은 별도 분석 집단이므로 다른 날짜 유형과 중복될 수 있다.

분석 결과 모든 날짜 유형에서 MAPE가 감소했다.

특히 공휴일 MAPE는 13.60%에서 12.87%로 0.73%p 개선되었다.

다만 보강 모델에서도 공휴일 MAPE는 평일보다 크게 나타났다. 이는 휴일 관련 피처를 추가하더라도 공휴일 수요를 완전히 설명하기는 어렵다는 의미다.

또한 근로자의 날은 테스트 기간에 2024년 5월 1일 하루만 포함되므로, 해당 수치를 근로자의 날 전체에 대한 일반적인 예측 성능으로 해석하지 않았다.

#### 5.6.4 2024년 5월 1일 예측 오차 분석

기존 모델에서 가장 큰 예측 오차가 발생했던 2024년 5월 1일을 별도로 확인했다.

| 항목 | 결과 |
|---|---:|
| 실제 이용량 | 11,868,225건 |
| 기존 모델 예측 | 16,981,073건 |
| 보강 모델 예측 | 13,870,909건 |
| 기존 절대백분율오차(APE) | 43.08% |
| 보강 절대백분율오차(APE) | 16.87% |
| APE 개선 폭 | 26.21%p |

기존 모델은 실제 이용량보다 약 511만 건을 많이 예측했으나, 보강 모델에서는 과대예측 규모가 약 200만 건으로 줄었다.

이에 따라 2024년 5월 1일의 APE는 43.08%에서 16.87%로 26.21%p 감소했다.

이는 기존 모델이 충분히 반영하지 못했던 근로자의 날과 휴일 관련 특성을 추가한 후 해당 날짜의 예측이 개선되었음을 보여준다.

다만 세 가지 휴일 피처를 동시에 추가했으므로, 개선 폭 전체를 `is_labor_day` 하나의 효과로 해석할 수는 없다.

#### 5.6.6 실험 결과 및 적용 판단

휴일 보강 모델은 동일한 테스트 기간에서 전체 MAPE를 0.10%p 낮추었고, 2024년 5월 1일의 예측 오차를 26.21%p 개선했다.

날짜 유형별 분석에서도 평일, 주말, 공휴일, 근로자의 날, 휴일 다음 날 모두 MAPE가 감소했다.

따라서 기존 달력 정보에 근로자의 날과 연속 휴일 정보를 추가하는 것이 이번 테스트 구간의 수요 예측에 도움이 되는 것으로 확인되었다.

다만 이번 실험은 단일 시간순 분할을 기준으로 수행했으며, 다른 연도의 근로자의 날과 연휴 구간에서 개선 효과가 유지되는지는 검증하지 않았다.

이에 따라 기존 기본 모델을 즉시 교체하지 않고 휴일 보강 모델을 개선 후보로 유지했다.

비교 실험 결과는 다음 파일에 별도로 저장했다.

- `models/holiday_feature_comparison.json`: 전체 및 날짜 유형별 성능 비교
- `models/holiday_feature_predictions.csv`: 테스트 날짜별 실제값과 두 모델의 예측값
- `models/holiday_feature_importance.csv`: 휴일 보강 모델의 변수 중요도

| 모델 | MAPE |
|---|---:|
| 날씨 포함 | 4.32% |
| 날씨 제외 | 6.25% |

집중호우 구간에서는 날씨 포함 모델의 MAPE가 1.93%p 낮았다.

전체 테스트 구간보다 집중호우 구간에서 날씨 변수의 예측 기여도가 크게 나타났다.

### 6.3 Walk-forward 비교

5개 시간순 검증 구간에서 날씨 변수 포함 여부를 비교했다.

5개 구간 중 3개 구간에서 날씨 변수가 성능을 개선했다.

그러나 구간별 MAPE 개선 폭의 단순 평균은 -0.02%p로 나타나 모든 시기에 일관된 개선 효과가 확인되지는 않았다.

이는 날씨 변수의 기여도가 평가 시기와 수요 구조에 따라 달라질 수 있음을 보여준다.

### 6.4 Permutation importance

테스트 데이터에서 각 특징의 값을 섞었을 때 MAE가 얼마나 증가하는지 확인했다.

주요 날씨 변수의 결과는 다음과 같다.

| 변수 | 순열 후 MAE 증가 |
|---|---:|
| `rain_mm` | 약 8,223건 |
| `precip_mm` | 약 5,466건 |

해당 값은 특징을 무작위로 섞었을 때 발생한 오차 증가량이다.

따라서 변수의 인과적 영향이나 이용량 감소량으로 해석하지 않는다.

## 7. 팬데믹에 따른 구조 변화

### 7.1 수요 수준 변화

시간순 검증에서 나타난 2020년 성능 저하의 배경을 확인하기 위해 2019~2024년 수요 변화를 추가 분석했다.

팬데믹 이후 지하철 이용량은 크게 감소했으며 이후 여러 해에 걸쳐 점진적으로 회복했다.

- 2020년 일평균 이용량: 2019년 대비 약 27.7% 감소
- 2024년 일평균 이용량: 2019년 대비 약 7.2% 감소

팬데믹 기간은 하나의 구간으로 처리하지 않고 팬데믹 이전, 급성기, 회복기, 엔데믹 이후로 구분했다.

국면별 수요를 비교할 때는 요일 구성 차이의 영향을 줄이기 위해 평일 데이터만 사용했다.

### 7.2 구조 변화와 예측 오차

2020년의 모델 성능 저하는 단순한 모델 오류만으로 보기 어렵고, 팬데믹으로 인해 기존 수요 패턴 자체가 변한 구조 변화와 연결하여 해석할 수 있다.

lag와 rolling 특징은 과거 수요 패턴을 이용하기 때문에 팬데믹처럼 수요 수준이 갑자기 바뀌는 상황에서는 새로운 수준에 즉시 대응하기 어렵다.

따라서 모델에서는 팬데믹 급성기와 회복기를 나타내는 특징을 사용하여 이러한 수준 이동을 구분할 수 있도록 했다.

다만 과거 팬데믹 국면을 특징으로 반영했다고 해서 향후 발생할 새로운 구조 변화를 사전에 정확히 예측할 수 있다는 의미는 아니다.

## 8. 팬데믹과 요일 구조

팬데믹은 전체 이용량만 감소시킨 것이 아니라 평일과 주말의 상대적인 수요 구조에도 영향을 준 것으로 나타났다.

팬데믹 급성기에는 주말 이용량이 평일 이용량보다 상대적으로 더 크게 감소했다.

이후 주말 수요도 다시 회복했지만 팬데믹 이전과 완전히 동일한 구조로 돌아왔다고 보기는 어렵다.

따라서 장기간의 지하철 수요를 분석할 때는 전체 이용량 수준의 변화뿐 아니라 요일별 이용 패턴의 변화도 함께 확인할 필요가 있다.

## 9. 결론

지하철 수요는 날씨 하나만으로 결정되지 않는다.

요일과 휴일, 직전 시점의 이용량, 장기적인 사회적 변화 등이 함께 수요에 영향을 준다.

이번 분석에서 확인한 주요 결과는 다음과 같다.

1. 평일·비공휴일 기준 연도·월 보정 후 강우일의 상대 이용량은 비강우일보다 1.41%p 낮았다.

2. 일 강우량 20mm 초과 구간에서는 상대 이용량이 0mm인 날보다 4.01%p 낮았다.

3. 날씨 변수를 포함한 모델은 전체 테스트 구간에서 MAPE가 0.20%p 낮았고, 집중호우 구간에서는 1.93%p 낮았다.

4. 날씨 변수의 예측 기여도는 검증 시기마다 달랐으며 모든 구간에서 일관된 성능 개선이 나타나지는 않았다.

5. 동일한 2022년 테스트 기간에서 미래 데이터를 포함한 혼합 학습의 MAPE가 2.11%p 낮았으나 실제 미래 예측 성능으로 해석할 수 없다.

6. 팬데믹과 같은 구조 변화는 수요 수준뿐 아니라 요일별 이용 패턴과 예측 성능에도 영향을 미쳤다.

7. 근로자의 날과 연속 휴일 관련 피처를 추가한 모델은 기존 모델보다 전체 MAPE가 0.10%p 낮았으며, 2024년 5월 1일의 예측 오차는 43.08%에서 16.87%로 감소했다.

8. 휴일 보강 모델의 공휴일 MAPE는 13.60%에서 12.87%로 개선되었으나, 여전히 평일보다 큰 오차를 보여 특수 날짜의 수요 예측에는 추가 개선이 필요하다.

특정 기간에서 모델 성능이 크게 저하될 경우 모델 자체의 문제만 확인하는 것이 아니라 데이터의 생성 구조가 변한 시점인지도 함께 확인할 필요가 있다.

또한 전체 평균 성능이 양호하더라도 공휴일이나 근로자의 날처럼 일부 날짜에 큰 예측 오차가 집중될 수 있으므로, 날짜 유형별 평가를 함께 수행하는 것이 중요하다.

이번 프로젝트에서는 데이터 정제와 탐색적 분석에서 시작하여 강우 효과 보정, 날씨 변수 기여도 검증, 시계열 모델 평가, 휴일 피처 보강, 팬데믹 구조 변화 분석까지 연결함으로써 지하철 수요를 시간에 따라 변화하는 데이터로 해석했다.

## 10. 한계와 향후 개선

### 10.1 데이터 범위

현재 데이터는 서울·수도권의 여러 철도 노선을 포함하지만 수도권 전철 전체를 완전히 포함하지 않는다.

따라서 분석 결과를 수도권 전철 전체의 결과로 일반화하는 데에는 주의가 필요하다.

### 10.2 강우 분석의 한계

강우 분석은 관측 자료의 연관성을 분석한 것으로 인과적 효과를 확정하지 않는다.

또한 통제 회귀분석의 HC1 표준오차는 시계열 자기상관을 직접 보정하지 않는다.

향후에는 시계열 자기상관을 고려한 추가적인 강건성 검증이 필요하다.

### 10.3 실제 예측 환경과의 차이

현재 모델은 실측 기상 데이터를 사용하므로 실제 기상 예보를 입력하는 환경과 예측 성능에 차이가 발생할 수 있다.

lag 및 rolling 특징도 과거 실측 이용량을 사용하므로 여러 미래 날짜를 한 번에 예측하는 상황에는 별도 설계가 필요하다.

### 10.4 팬데믹과 외부 구조 변화

팬데믹과 같은 구조 변화는 과거 수요만으로 예측하기 어렵다.

향후에는 대규모 행사, 교통 정책 변화, 운행 장애 등의 외부 요인을 추가로 결합하여 갑작스러운 수요 변화를 설명할 수 있도록 개선할 수 있다.

또한 연도별로 관측되는 역의 수와 구성이 달라질 수 있으므로, 팬데믹 이전과 이후의 회복률을 비교할 때는 동일한 역 집합을 기준으로 한 추가 검증이 필요하다.

### 10.5 데이터 품질과 재현성

SQLite 적재 과정에서 제외된 372행에 대해 고유 키 중복 여부, 필수 키 결측 여부, 이용량 차이, 발생 위치와 전체 이용량 대비 영향도를 검증했다.

검증 결과 제외된 372행은 모두 원본 내부의 고유 키 중복에 해당했으며, 필수 키 결측은 발견되지 않았다.

중복으로 제외된 행의 이용량 합계는 230,226건으로 전체 원본 이용량 대비 약 0.000829%였다.

다만 중복이 경의선의 특정 역에 집중되어 있고, 동일 키에 서로 다른 이용량이 기록되어 있어 개별 역·날짜 단위 분석에서는 영향이 더 클 가능성이 있다.

또한 원본 데이터만으로 중복 레코드의 발생 원인과 집계 의미를 확정할 수 없으므로, 기존 `INSERT OR IGNORE` 정책을 유지하고 해당 한계를 명시했다.

새로운 가상환경에서 의존성을 처음부터 설치하고 전체 파이프라인을 실행하는 재현성 검증은 아직 수행하지 않았다.

### 10.6 휴일 예측 성능의 한계

휴일 보강 모델은 기존 모델보다 전체 MAPE와 날짜 유형별 MAPE가 개선되었지만, 단일 시간순 테스트 구간을 기준으로 평가했다.

특히 근로자의 날은 테스트 데이터에 2024년 5월 1일 하루만 포함되어 있으므로, 해당 날짜의 오차 개선을 다른 연도의 근로자의 날에도 동일하게 적용할 수는 없다.

또한 이번 실험에서는 세 가지 휴일 피처를 동시에 추가했기 때문에 개별 피처가 성능 개선에 기여한 정도를 분리하여 확인하지 않았다.

`holiday_streak_length`는 일반 주말과 공휴일이 연속되는 기간을 함께 계산하므로, 설날·추석과 같은 명절 연휴만의 특성을 독립적으로 표현하지는 않는다.

향후에는 다음과 같은 추가 검증이 필요하다.

- 연도별 시간순 검증을 통한 휴일 보강 모델의 성능 안정성 확인
- 근로자의 날, 휴일 다음 날, 연속 휴일 길이 피처의 개별 기여도 비교
- 설날·추석 등 명절 연휴 전용 피처 추가 검토
- 공휴일 목록과 임시 공휴일 반영 여부 재검토
- 휴일 유형별 예측 오차와 과대·과소예측 경향 추가 분석

따라서 현재 휴일 보강 모델은 성능 개선 가능성이 확인된 후보 모델로 유지하며, 추가 검증 후 기본 모델 반영 여부를 결정할 예정이다.
